# Contributing to YaskCode Academy

Thank you for helping improve YaskCode Academy. We build learning experiences for learning Software Engineering by doing Software Engineering—with pedagogical intent, evidence, review and respect.

## Two kinds of participation

**Academic participation** includes course activities, exercises, assessed submissions and work in private repositories. It may be governed by teaching instructions, privacy, shared authorship and institutional rules.

An **accepted open-source contribution** is an item explicitly proposed for publication, reviewed, accepted and recorded by YaskCode Academy. Academic work is not automatically public or accepted open source. Publication needs an explicit decision, quality review, attribution, appropriate licensing, consent where needed and no sensitive information.

## Ways to contribute

You can improve educational resources and learning paths; practical projects and authorized reference material; code, automation and tools; documentation; translations; accessibility; design; testing; and technical review. For substantial work, first find or open an Issue to confirm scope, audience, licensing and publication route.

## Basic workflow

1. Read [GOVERNANCE.en.md](GOVERNANCE.en.md), this document, [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), [SECURITY.md](SECURITY.md) and [LICENSING.md](LICENSING.md). The Spanish documents remain authoritative where an interpretation differs.
2. Review repository-specific guidance and discuss the work in an Issue.
3. Fork or create a descriptive branch as directed by the repository.
4. Submit a focused Pull Request, linking the Issue when available.

Describe the educational and technical impact, validations performed, substantive use of generative AI, and licensing/attribution considerations. Maintainers may request changes; acceptance is not automatic. Review considers mission fit, quality, security, accessibility, documentation, academic integrity, licensing and maintainability.

## Expectations

Educational contributions should state purpose, audience, prerequisites, expected learning outcome, clear instructions, sources when relevant and validation criteria. Technical changes should follow repository instructions, include reasonable tests and report checks that could not be run.

Spanish is the primary language. Translations must preserve meaning, examples, references and warnings; human review matters. Use accessible structure, helpful alt text, clear language and descriptive links.

Do not submit private student work, assessment answers, unauthorized material, secrets, personal data or sensitive vulnerabilities. Generative AI may assist but does not replace human responsibility: verify outputs, protect data, avoid plagiarism and disclose substantive use in the Pull Request. By contributing, you agree to the [Code of Conduct](CODE_OF_CONDUCT.md) and confirm that accepted work may be distributed under the applicable policy in [LICENSING.md](LICENSING.md).

The Spanish version, [CONTRIBUTING.md](CONTRIBUTING.md), is the authoritative version if interpretation differs.

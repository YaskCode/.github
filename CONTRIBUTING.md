# Contribuir a YaskCode Academy

Gracias por querer mejorar YaskCode Academy. Aquí construimos experiencias para aprender Ingeniería de Software haciendo Ingeniería de Software: con intención pedagógica, evidencia, revisión y respeto por las personas.

## Dos formas de participar

**Participación académica** incluye actividades de cursos, ejercicios, entregas, evaluaciones y trabajo en repositorios privados. Puede estar sujeta a instrucciones docentes, privacidad, autoría compartida y normas institucionales.

**Contribución open source aceptada** es un aporte que se propone para publicación y es revisado, aceptado y registrado por YaskCode Academy. No toda entrega académica debe ni puede publicarse. La apertura requiere una decisión explícita, revisión de calidad, atribución, licenciamiento, consentimiento cuando aplique y ausencia de información sensible.

## Formas de contribuir

- recursos y rutas educativas;
- proyectos prácticos, ejemplos, ejercicios y soluciones de referencia cuando estén autorizados;
- código, automatización, plantillas o herramientas;
- documentación, revisión editorial y enlaces;
- traducciones que preserven la intención pedagógica;
- accesibilidad, diseño inclusivo y mejora de la experiencia de aprendizaje;
- pruebas, reproducción de errores y revisión técnica.

Antes de invertir trabajo amplio, abre o busca un Issue para confirmar alcance, público, licencia y canal de publicación.

## Onboarding básico

1. Lee [GOVERNANCE.md](GOVERNANCE.md), este documento, [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), [SECURITY.md](SECURITY.md) y [LICENSING.md](LICENSING.md).
2. Busca Issues, documentación y normas específicas del repositorio.
3. Comenta en el Issue o abre uno para proponer el trabajo.
4. Haz fork o crea una rama según el flujo del repositorio.
5. Entrega un Pull Request pequeño, claro y trazable.

## Issues, ramas, commits y Pull Requests

Usa Issues para preguntas reproducibles, propuestas, problemas de contenido, accesibilidad, documentación o mejoras técnicas. No publiques secretos, datos personales, calificaciones, entregas privadas o vulnerabilidades sensibles: consulta [SECURITY.md](SECURITY.md).

Crea una rama descriptiva desde la rama indicada por el repositorio. Mantén los commits enfocados y comprensibles; explica el cambio y su razón. El Pull Request debe enlazar el Issue cuando exista, describir impacto pedagógico y técnico, indicar pruebas o validaciones realizadas, revelar uso sustantivo de IA generativa y confirmar que se respetan licencias y atribución.

La revisión puede solicitar cambios. La aceptación no es automática: evalúa pertinencia para la misión, calidad, seguridad, accesibilidad, documentación, integridad académica, licenciamiento y mantenibilidad. La automatización puede validar el código; la revisión de ingeniería valida la solución.

## Calidad educativa y técnica

Las contribuciones educativas deben identificar propósito, audiencia, requisitos previos, resultados de aprendizaje o habilidad esperada, instrucciones claras, fuentes cuando correspondan y criterios de validación. Evita presentar como universal una experiencia particular o material no verificado.

Las contribuciones técnicas deben seguir las instrucciones del repositorio, incluir pruebas razonables y no degradar seguridad, accesibilidad ni documentación. Ejecuta las verificaciones disponibles antes de abrir el Pull Request y reporta lo que no pudiste ejecutar.

## Traducción y accesibilidad

El español es el idioma principal. Las traducciones al inglés u otros idiomas deben conservar significado, ejemplos, referencias y advertencias; no son una sustitución mecánica de la revisión humana. Considera lenguaje claro, estructura de encabezados, texto alternativo útil, contraste, enlaces descriptivos, navegación con teclado y formatos accesibles.

## Integridad académica y uso responsable de IA

No envíes respuestas de evaluación, trabajos de estudiantes, contenido obtenido sin autorización ni material que facilite fraude académico. Respeta los límites de cada experiencia de aprendizaje y las políticas institucionales aplicables.

La IA generativa puede apoyar ideación, redacción, traducción, revisión o código, pero no reemplaza responsabilidad humana. Verifica resultados, protege datos y secretos, evita plagio y atribuye fuentes cuando corresponda. Declara en el Pull Request el uso sustantivo de IA que haya influido materialmente en el aporte, junto con la revisión humana realizada.

## Propiedad intelectual, atribución y licencias

Solo contribuye contenido que puedas compartir. Conserva atribuciones, citas, avisos y condiciones de obras de terceros. Al enviar un Pull Request, confirmas que tienes derecho a aportar el material y que aceptas que, si se integra, se distribuya bajo la licencia aplicable definida en [LICENSING.md](LICENSING.md). La licencia concreta de código o materiales educativos se indicará en cada repositorio o contenido antes de su publicación.

## Comportamiento esperado

Participa de forma respetuosa, constructiva y paciente. Al contribuir aceptas el [Código de Conducta](CODE_OF_CONDUCT.md). Para dudas generales utiliza los canales públicos definidos por el repositorio; para asuntos sensibles sigue las indicaciones de seguridad o conducta aplicables.
